# Judge QA Matrix — SAT-SA / SENTRA (Phase 15 Adversarial QA)

Verdict vocabulary used in this matrix:
- `CONFIRMED` — reproduced with recorded evidence in this audit.
- `CONFIRMED (code)` — established by structural reading of the implementation; reproduction described.
- `DISPROVEN` — hypothesis was tested and refuted.
- `OBSERVED` — observed behaviour that is either acceptable-by-design or needs a supervisory judgement (not a defect).
- `FIXED` — remediated during this phase (code, tests, and/or docs; smoke + full-suite re-verified).

Reproduction context: Python 3.14.4, `.\backend\.venv\Scripts\python.exe` (venv at `backend\.venv`), repo root `O:\sat-sa`. Tests run as `.\backend\.venv\Scripts\pytest.exe -q tests`.

## 1. Security defects

| ID | Finding | Verdict | Evidence | Risk |
|---|---|---|---|---|
| C1 | **Path-sandbox prefix bypass.** `safe_resolve_path` (`backend/app/api/security.py:22`) checks `str(resolved_requested).startswith(str(resolved_base))` — a string-prefix test, not a filesystem-containment test. A *sibling* path whose string begins with the base's string passes. E.g. base `O:\sat-sa\data` admits `O:\sat-sa\data_evil\secrets.txt`. | FIXED | `safe_resolve_path` now verifies containment via `base in candidate.parents` (pathlib ancestor test, case-insensitive on Windows), so sibling prefix collisions and verbatim absolute paths are rejected (`backend/app/api/security.py:9-27`). Smoke: `O:\…\data2` → `PathTraversalError`; live `POST …/register` traversal + absolute-outside-base both 400. | High |
| C2 | **`data/data` path bug in blockchain registration default.** `backend/app/api/blockchain.py:68` computes `settings.data_dir / "data/processed"`. Since `settings.data_dir` already is `…\data`, this is `O:\sat-sa\data\data\processed`, which does not exist; the endpoint silently falls back to `settings.data_dir` (the whole `data` directory) as the submission. | FIXED | Default now resolves `data/processed` → else `data/synthetic` → else `data` (`blockchain.py:67-74`), so the registration default reaches canonical Parquet instead of the raw `data` root. | High |
| C14 | **Absolute path disclosure in API `detail` for blockchain errors.** Endpoint-level handlers return `detail=str(exc)` (`backend/app/api/blockchain.py:77`, `:110`), and `hash_submission_directory` raises `NotADirectoryError(f"Directory not found: {path}")`. | FIXED | Registration errors are logged server-side and surfaced as a generic, path-free `400` detail ("Submission data directory is not available…"); the absolute path no longer leaves the process (`blockchain.py:78-91`). Smoke asserts no `O:\` / filename in the response body. | Medium |
| C15 | **Payload-size limit relies only on `Content-Length`.** `PayloadSizeLimitMiddleware.dispatch` (`backend/app/api/security.py:38-47`) checks the `content-length` header only; chunked transfer encoding or any request omitting the header bypasses the 100 MB cap. | FIXED | Middleware now runs a pre-flight `content-length` check **and** reads the body to enforce the cap on streamed/headerless requests (413). Starlette's `_CachedRequest` replays the cached body downstream, so normal JSON handling is unchanged. Smoke: oversized `content-length` → 413 while valid requests pass. TestClient never exercised chunked, but the body-length path takes over when no valid header exists. | Medium |
| C9 | **Stored-XSS in rendered HTML dossier.** `render_entity_dossier_html` (`backend/app/analytics/supervisory_risk/dossier.py:158-492`) interpolates entity-controlled fields (name, sector, rationale, summaries, directives) into HTML without escaping. | FIXED | `render_entity_dossier_html` deep-escapes every string in the dossier payload (`html.escape`, numbers untouched for `{:.2f}` formatting) before interpolation (`dossier.py:166-186`). Smoke injects `<script>`/`onclick` payloads into name, directive, and rationale — 0 raw payloads survive. | Medium–High |
| C18 | **Broad swallowed exceptions + GET side effects in blockchain service.** `seed_initial_commitments` (`backend/app/blockchain/service.py:171-216`) catches `except Exception: pass` for every register; `list_records()` (`:218-223`) and `get_all_history()` (`:225-230`) call `seed_initial_commitments()` when empty — i.e. **read GET endpoints mutate ledger state** and failures silently disappear. | FIXED | `list_records`/`get_all_history` are now read-only; seeding only happens via the explicit seed path. `seed_initial_commitments` logs failures via `logger.warning` instead of swallowing them. No tests depended on read-side seeding. | Medium |

## 2. Analytics correctness

| C5 | **NS001/NS002 negative-space risk normalisation inverted.** For NS001/NS002, findings set `observed = assets_with_alert_activity` / `critical_assets_with_activity` (activity *present*), with `gap = 1 - coverage`. `_norm_ns_ratio` (`backend/app/analytics/supervisory_risk/normalization.py:236-250`) normalises `observed/denominator*100` — so **more observed activity raises the monitoring risk signal**, opposite of the intent for a coverage-gap finding. | FIXED | NS001/NS002 now route through `_norm_ns_gap` (`normalization.py:267-281`) using the finding's `gap_value` (`1 - coverage` / `inactive_critical ÷ critical_assets`), so absence of expected evidence drives risk. | C6 | **R005 normalisation quasi-silent.** `_norm_r005` (`normalization.py:170-195`) divides the finding's `observed_value` (a **rate**, e.g. 0.8889) by `expected_monitored_assets` (count) × 100. R005/CSE-007: 0.8889/45 → 1.98/100. The direction is *not* inverted (higher coverage → higher score, also wrong) but the magnitude is negligible either way. | CONFIRMED | Live R005 rows: CSE-007 `observed=0.8889, population=45`; CSE-008 `0.7561, population=41`.
